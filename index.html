Agile Team Charter

Evidence

The GrandCaddy project was built using an Agile Team Charter that defined the team’s purpose, shared values, roles, working agreements, and boundaries. The charter focused on the product’s customer journey and kept the team aligned around practical outcomes.

Reflection

This charter was important because it created a shared understanding of how the team should work together. It helped us avoid scope creep and kept the project aligned with user needs, especially in relation to trust, usability, and clarity of communication.

User Stories and Tasks

Evidence

The main project story I developed was the Caddy/Helper user story. It focused on the helper journey from registration and profile creation to browsing available tasks, viewing task details, and accepting or rejecting a task.

  • US-2.1: Onboarding flow
  • US-2.2: Profile creation
  • US-2.3: Browse available tasks
  • US-2.4: View task details
  • US-2.5: Accept or reject a task

Reflection

Writing the user stories helped me understand that requirements must be written from the user’s perspective. It also showed me that tasks should be small enough to be completed and tested in a structured way.

Product Backlog

Evidence

The GrandCaddy product backlog was organised using priority levels based on what was most important for the product. The must-have items included the main customer journey, helper journey, and data functions required to support the application.

Reflection

The backlog taught me that prioritisation is more than ordering tasks; it is about deciding what must be built first to create a safe and usable system. The product was designed around trust and user confidence.
